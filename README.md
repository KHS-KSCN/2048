# 2048 — 使用说明（index.html 用户端）

`index.html` 是 `2048.c`（Web 服务器版 2048 游戏）的单文件复刻版：游戏逻辑与原版 1:1 一致，
所有后端接口都映射到了本地调用，因此**无需任何服务器**，双击用浏览器打开即可玩。

## 快速开始

1. 用任意现代浏览器（Chrome / Edge / Firefox / Safari）直接打开 `index.html`
   （双击即可，`file://` 协议下可正常运行）。
2. 用键盘玩游戏：

   | 按键 | 动作 |
   |---|---|
   | 方向键 ↑ / W | 向上合并 |
   | 方向键 ↓ / S | 向下合并 |
   | 方向键 ← / A | 向左合并 |
   | 方向键 → / D | 向右合并 |

3. 界面右上角实时显示分数；合成出 2048 显示 "You Win!"，无步可走显示 "Game Over!"。

## 按钮说明

| 按钮 | 作用 |
|---|---|
| **New Game** | 开一局新游戏（会丢弃当前局面和分数）。 |
| **Undo** | 撤销上一步，最多可撤销 **3** 步（与原版一致）。无步可撤时提示 "No moves to undo"。 |
| **Save** | 保存当前游戏：① 写入浏览器 localStorage（刷新页面后自动恢复）；② 同时把 `2048_save.dat` 下载到本地。保存成功提示 "Game saved"。 |
| **Upload** | 上传并打开之前保存的 `.dat` 存档文件（见下方流程）。 |
| **Exit** | 退出游戏，显示 "Goodbye!" 页面（对应服务版的 "Server shutting down"）。 |

## Upload 使用流程

1. 点击 **Upload**。
2. **确认覆盖**：如果当前界面分数不为 0（即已经开始得分），会先弹出确认框
   "Current score is X. Upload will overwrite the current game. Continue?"，
   点 **OK** 才继续上传，点 **Cancel** 取消操作、保留当前局面。
   分数为 0 时不弹确认，直接进入下一步。
3. 在文件选择框中挑选一个 `.dat` 存档文件（即之前用 Save 下载、或由 `2048.c` 服务器版
   生成的 `2048_save.dat`）。
4. 结果：
   - **成功**：界面立刻切换为存档中的局面（棋盘、分数、胜负状态、可撤销历史），
     消息区显示 `Loaded saved game from <文件名>`。
   - **失败**（文件不是 284 字节、内容非法、或读取出错）：**当前界面原样保留**，
     消息区显示 `Failed to open <文件名>: ...`，可重新选择正确的文件。

> 提示：Upload 读取的是二进制 `.dat` 文件，与浏览器 localStorage 无关，
> 所以可以在不同浏览器、不同电脑之间互传存档。

## 存档文件（2048_save.dat）格式

小端（little-endian）二进制，共 **284 字节**，与 `2048.c` 的 `save_game()` 逐字节一致：

| 偏移 | 长度 | 内容 |
|---|---|---|
| 0   | 64 | 棋盘 4×4，int32，行优先（0 = 空格） |
| 64  | 4  | 分数 score |
| 68  | 4  | over（0/1） |
| 72  | 4  | won（0/1） |
| 76  | 204 | 3 个撤销快照，每个 68 字节 = 棋盘 64 + 分数 4 |
| 280 | 4  | 快照计数 hc（0~3） |

Save 生成的文件可被 `2048.c` 服务器版的 `load_game()` 直接读取，反之亦然。

## 常见问题

- **刷新页面后游戏还在？** Save 时同时写了 localStorage，刷新后自动恢复；
  这是原有行为，与 .dat 下载互不影响。清掉站点数据或换浏览器后需要重新 Upload。
- **Upload 同一个文件二次选择没反应？** 不会发生：每次选择后输入框会复位，
  连续两次选同一个文件也能正常重新加载。
- **分数没变但想恢复上一局？** 用之前下载好的 `.dat` 文件 Upload 即可
  （只要当前分数为 0 无需确认，非 0 会先弹窗确认）。
